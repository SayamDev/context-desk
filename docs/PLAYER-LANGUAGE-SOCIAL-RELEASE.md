# Player, subtitle language and social delivery — 1 November 2026

This revision implements the two release blockers highlighted in the user's 10:26 screenshot and the social-export request. It extends the existing V2 studio rather than replacing its working media engine. The larger consolidated brief remains the product roadmap; this release is not a claim of Premiere/CapCut parity, universal capture, perfect translation or competition success.

## Diagnosed faults and fixes

**Player reset.** `HTMLMediaElement.src` expands to an absolute URL, while managed media in project state uses `/api/...` paths. `renderEditor()` compared those unequal strings and reassigned the same source. In the browser, changing the translation provider during playback reproduced a pause and a jump back to IN. Source identity now compares resolved URLs and leaves the media element untouched when the source is unchanged. Inspector updates, autosave and caption changes can update the UI without loading media again.

This establishes a confirmed reset path; the user's historical volume-only failure in the native source monitor was not independently reproduced. The new Studio volume path was exercised directly on both a synthetic recording and the saved Arabic episode. Pressing an already-active Studio navigation item also leaves playback alone.

Volume, mute, speed and fullscreen now have explicit Studio controls. Volume/mute/rate mutate only the media element and their own browser preferences, independently of edit history and project autosave. Space on a focused button performs that button's action rather than also invoking the global playback shortcut. Browser preferences survive refresh; playback does not automatically resume. Buffering/error feedback uses actual media events. Existing restart, loop, seek and trim remain canonical.

**Language drift.** `liveCaptionLanguage` previously guided discovery but clips retained independent `captionLanguage` values; fresh analysis also started by selecting Original. The project output now governs every inherited clip, new results and server-rendered exports. A visible “Use a different language for this clip” checkbox creates a persisted explicit override. The priority is clip override → saved project target → user default. Legacy per-clip active-track values alone do not override an explicit project output. Original speech remains a separate transcript/track.

Selecting a project language queues missing tracks, with at most two concurrent translations. A missing target has no fallback to the original language. The UI shows preparation, queue and retry states. Cached/completed tracks are reused. Late translations retain the active language, respect changed original text and human corrections, and can populate a reopened project safely. Export resolves the same policy and refuses unreviewed/missing displayed tracks when captions are enabled. An editor can still explicitly omit captions.

Completed translation responses are cached in SQLite using provider/model version, source/target language, dialect, style, glossary and source lines. In-process duplicates share a request. Failed or abandoned provider attempts require explicit retry; they are not automatically replayed after restart. Browser translation dispatch itself is not a new server Jobs worker: closed-tab pending work is recovered on project reopen using saved tracks/cache, not claimed to continue unattended. Existing discovery/full-recording subtitle/export jobs remain durable backend workers.

## Social delivery that actually works

Studio's **Export for** offers TikTok, Instagram Reels, Facebook Reels, YouTube Shorts, YouTube video and Custom. Presets set aspect, 1080p and MP4 together. Fit preserves the whole picture; Fill/manual framing remains available. A 1080p file from a smaller source is an upscale, not restored source detail. Changing underlying settings requires reapplying the named preset or choosing Custom, so a mislabeled export is not silently produced.

Finished Jobs show the saved video/SRT, exact caption languages, destination link and the instruction to download then select the file in the platform. Compatible browsers offer the native file share sheet, with a 100 MB preparation cap and a download fallback. The sheet is optional; platform availability depends on the browser/OS. No OAuth account, upload completion, scheduled post or published post is fabricated. Opening the destination does not attach the file automatically. Native sharing into a destination app and actual account posting have not been validated here.

YouTube Shorts checks the documented three-minute limit. Other account-specific duration, rights and upload limits are checked by the destination platform. [YouTube's Shorts guide](https://support.google.com/youtube/answer/15424877) supports the square/vertical ≤3-minute classification. [TikTok Direct Post](https://developers.tiktok.com/docs/en/content-posting-api-get-started) requires a registered client/authorization and describes audit restrictions. [YouTube uploads](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert) require OAuth upload authorization. Meta's Instagram/Facebook publishing pages could not be retrieved during this pass (access error/429); no unverified permission or account-eligibility rules were implemented from guesses. Direct OAuth publishing/scheduling is still a separate integration.
