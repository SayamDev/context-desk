# Context Desk: complete source-to-feature inventory

Research and baseline inspection: **1 November 2026**. This document translates all supplied references into a production backlog. It is an inventory of useful capabilities, evidence and dependencies, not a claim that Context Desk matches these products or that feature count predicts competition results.

The ambition is a complete, approachable production studio: add footage, discover several worthwhile moments, understand their context, edit them, apply a reusable identity, deliver usable files, and manage the resulting work. Advanced functions should remain accessible inside that journey rather than becoming disconnected demonstration screens.

## How to read this record

- **P — public interface:** controls/text returned from an unauthenticated official page. This does not mean its signed-in editor was operated. A promotional screenshot is an illustration, not an observed working editor.
- **D — documented:** first-party documentation describes the feature. No competitor processing or rendering was tested here.
- **M — vendor claim:** advertised intelligence, speed, accuracy, quality, engagement, tracking or performance. It is not a benchmark result.
- **S — source inspection:** a public repository file contains relevant implementation or licence text. Static reading is not execution, security review or proof of the hosted release.
- **I — original implementation proposal:** what Context Desk should build. A proposal is never competitor evidence.
- **Baseline:** present in inspected code or recorded in the current `STATUS.md`. Existing verification claims below are attributed to that status, not newly repeated by this research task.
- **In flight:** being changed by parallel implementation work in this session; acceptance remains pending. File presence does not establish browser behavior or export fidelity.
- **Gap:** no complete implementation demonstrated in the baseline. A visible control alone does not close a gap.

No competitor login, paid job, publication, account connection, source-code incorporation or purchase was performed. Sources are official product/help pages and official repositories only. Search-engine snippets were used to locate first-party pages, not to establish claims about unrelated products. Facts can change after this date.

Its coverage reports distinguish source transcription from story checks. A complete speech index is not proof that every event was understood, and a zero-result short test is not whole-episode editorial validation.

## Implementation sequence and completion gates

This is sequencing of the full ambition, not a reduced feature list or permanent exclusion. The current session can build useful local foundations without claiming unavailable accounts, rights or production infrastructure.

1. **Finish the everyday local studio.** Accept Home/resume/routes, clip navigation, inspector organization, reliable selected playback, caption looks/kits and rendered audio controls. Proof: an actual project is opened, edited, refreshed and rendered; visual inspection alone is insufficient.
2. **Make discovery materially better.** A complete reusable transcript index, sentence-aligned variable candidates, deduplication, source context and precise trims. Proof: a complete rights-cleared recording yields several human-accepted distinct clips and exposes missed/unreviewed material. Do not accept merely adding more evenly spaced windows.
3. **Accept edits and interchange in real tools.** Timed-line cut decisions and FCP7 XML are now implemented; verify that rendered cuts match preview and target NLE imports recover the intended sequence. Media handles/portable packaging and CMX EDL remain separate gaps. A downloadable XML file proves serialization only until actual import is checked.
4. **Add production layers.** Scene-aware reframing, split layouts, owned/licensed B-roll, covers, sound beds/ducking, effects and optional advanced NLE controls. Proof: layers share canonical edit state and are present in the final file, not just in a settings panel.
5. **Validate and extend external/collaborative services.** Local encoder ingest and YouTube/TikTok adapter foundations now exist. Actual authorized account publication, platform live adapters, consented dubbing, scheduling, teams, API/MCP and campaign packaging require separate completion/evidence. Local or fake transports do not clear account/rights gates.
6. **Keep quality evaluation continuous.** Whole episodes, native-dialect review, sustained live capture and maximum resource stress are release gates across the sequence. More capabilities do not eliminate these gates.

## Research limitations and maintenance

This is broad primary-source feature research, not a signed-in competitor audit, subscription recommendation, measured quality comparison or legal opinion. Public claims frequently exceed their directly documented conditions. Restream streaming and post-stream Clips must stay distinct; OpusClip and AI Producer must stay distinct; campaign marketplaces and editing engines must stay distinct.

No reliable detailed first-party content was obtained for Reach.cat or Clipping.io, and “native clipping programs” remains ambiguous. These are unresolved evidence rows, not silently omitted references or invented functionality. Do not adopt third-party reviews as substitutes for official product evidence.

OpenShorts links reference mutable `main`; any reuse must pin a revision, inspect each proposed file and all runtime/model licences, preserve required notices and exclude incompatible `cloud/` code. Its selection helpers demonstrate segment-aligned windows, balanced batches, overlap deduplication and word-boundary adjustment; they do not validate engagement prediction. Its [edit builder](https://raw.githubusercontent.com/mutonby/openshorts/main/edit_builder.py) validates a constrained effects list before building FFmpeg filters; this supports the architectural pattern, not copying unrestricted generated commands.

After the implementation work completes, update only rows backed by actual acceptance evidence and link that evidence. Source pages and plan restrictions should be refreshed before making purchasing, interoperability or platform-support commitments. Keep known limitations in `STATUS.md` synchronized; do not let this inventory become a second conflicting release status.
